Daily Workflow

8 steps, fully guided by the app

From opening the laptop to submitting wires to IVP — the entire morning routine, in order.

01

Open ApolloCAM in your browser

Run streamlit run app.py from the apollocam folder. The app opens at http://localhost:8501. The Dashboard loads and shows the last known positions.

02

Import today's JPM position file

Navigate to Import Data. Drag the JPMorgan daily statement (CSV or Excel). The app detects column names automatically — even if JPM changes the column order. Validates fund codes against the master and shows a preview before committing.

ℹ️ Supports any JPM column naming convention — 20+ alias mappings built in
03

Check the Dashboard for alerts

Return to the Dashboard. The KPI strip shows RED / AMBER counts at a glance. Any RED fund triggers an alert banner with fund name and deficit amount. The 11-fund grid is colour-coded — no reading required.

04

Review fund details on Status Review

The Status Review page shows a full table with every fund's cash balance, floor, ceiling, and surplus/deficit. Filter by status, sort by priority or cash amount, and export as CSV for records.

05

Run Proposals and approve wires

Navigate to Proposals. Click Run Proposals — the engine calculates which RED funds need wires, identifies the source fund, and computes the exact amount. Each proposal shows a before/after balance preview. Select APPROVE, SKIP, or HOLD per proposal, or click Approve All Wires for one-click sign-off.

💡 FX conversion proposals appear below wire proposals — same approve/skip workflow
06

Generate loader files

Navigate to Loaders. Click Generate All Loaders. Three files are built instantly with all SSI details, batch IDs, and references pre-populated. Download individually or as a ZIP. Each file shows an SHA-256 hash for integrity verification.

📁 Files: IVP_B20260601-001.xlsx · Trade_B20260601-001.csv · SpotFX_B20260601-001.xlsx
07

Submit to IVP and update wire status

Upload the IVP loader file to the IVP platform as usual. Then return to the Wire Status page and advance each wire from LOADER_GENERATED → SUBMITTED. When confirmations arrive, enter the confirmation reference and mark CONFIRMED.

08

Review Audit Log (EY requirement)

The Audit Log records every import, approval, override, and loader generation — immutably. Filter by date or action type. Export filtered results as CSV for EY review. No one can delete or modify entries — enforced at the database level.

Status Model

Four colours. One look. Instant decision.

Every fund is assessed against two thresholds: a floor (minimum safe cash) and a ceiling (maximum before BLUE alert). The AMBER buffer (default 110% of floor) gives an early warning zone.

🔴 RED

Fund cash is below the minimum floor. A wire transfer is needed today. Immediately triggers a proposal and an email alert.

cash < floor

🟡 AMBER

Cash is above floor but below the early-warning threshold. Not critical yet, but worth watching — particularly if pipeline calls are expected.

floor ≤ cash < floor × 1.10

🟢 GREEN

Cash is in the healthy operating band — above the AMBER threshold and below the ceiling. No action required.

floor × 1.10 ≤ cash ≤ ceiling

🔵 BLUE

Cash exceeds the ceiling. The fund is over-capitalised and may be a candidate to source wires for RED funds elsewhere in the complex.

cash > ceiling

Wire Proposal Logic

How the engine picks which wire to send

The engine sorts RED funds largest-deficit-first, then routes each wire from the fund's designated source — updating balances sequentially so no source is over-drawn.

Step-by-step decision process

1

Identify all RED funds

Find every fund where cash_balance < floor

2

Sort by deficit — largest first

Most urgent cash need gets funded first

3

Look up the source fund (routing_source)

Each fund in the master table names its funding source

4

Wire = MIN(deficit, source available above floor)

Never drain the source below its own floor

5

Update source balance and move to next RED fund

Sequential logic prevents the same source being over-used

Setup Guide

From zero to running in 10 minutes

ApolloCAM runs on a standard Windows laptop with Python installed. No cloud, no servers, no IT involvement required.

Prerequisites

  • Python 3.11 or higher — python.org/downloads
  • Git installed (for cloning the repository)
  • Internet connection for first-time setup (downloads packages)
  • JPMorgan daily position file (CSV or Excel format)
  • Windows 10/11, macOS, or Linux laptop
💡 Tip

ApolloCAM stores everything in a single SQLite file (data/apollocam.db). Back this file up daily — it contains all your positions, proposals, and audit history.

⚠️ Important

Never commit .env or apollocam.db to version control. Both are in .gitignore by default.

One-time installation

# Step 1 — Clone the repository git clone https://github.com/your-org/ApolloCAM cd ApolloCAM/apollocam # Step 2 — Create a virtual environment python -m venv .venv source .venv/bin/activate # Windows: .venv\Scripts\activate # Step 3 — Install dependencies pip install -r requirements.txt # Step 4 — Copy environment template cp .env.example .env # Edit .env to add SMTP settings (optional) # Step 5 — Launch the app streamlit run app.py

The browser opens automatically at http://localhost:8501. The database is created and seeded with all 11 fund masters on first run.
