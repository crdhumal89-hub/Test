## 3. Architecture (the thing that shapes everything else)

The delivered file is **not** a flat app. It is a launcher shell holding two complete HTML
documents embedded as one-line JS string literals, assigned to `iframe.srcdoc`:

```
window.MOD_TRACE    = "<!DOCTYPE html>..."   // 323,592 chars decoded
window.MOD_TRACEPRO = "<!DOCTYPE html>..."   // 933,176 chars decoded  <- the target
```

The two literals use **different** escaping conventions (MOD_TRACE keeps raw UTF-8,
MOD_TRACEPRO writes `\uXXXX`). `tools/codec.js` reproduces both byte-exactly;
`node tools/verify_roundtrip.js` proves `join(split(x)) === x`, and
`extract -> build` reproduces the original **byte for byte** (`cmp` clean).

TRACE-Pro's seven tabs: `lt` Look-Through, `rfx` Look-Through Pricing, `str` Structure,
`sim` Simulator, `own` Ownership Breakout, `iss` Issue Log, `gls` Glossary.
Structure, Simulator and Glossary were not restyled.

**All engine functions are global** (`renderTree`, `renderWaterfall`, `renderRFX`,
`recomputeR`, `liveMVof` ...) and the module's top-level `const`/`let` (`MODEL`, `EMB`,
`REVISE`, `U`, `Uv`, `expanded`) are in the shared global lexical scope. That is why the
whole change set could be **additive**: the new script wraps the render functions instead
of editing them, so not one line of calculation code was touched.

### Decision taken by me and logged (low risk, evidenced)

**The subtotal assertion covers Derived MV only.** Measured additivity over all 44 parent
groups:

| column | groups | tie to the cent | worst break |
| --- | --- | --- | --- |
| **Derived MV** | 44 | **44 (100%)** | - |
| Revised MV | 44 | 34 | APRAIL2 $272,162 |
| NAV | 3 | 2 | DEUCE1DC $0.018 |

Revised MV is repriced from each vehicle's own NAV rather than summed bottom-up, and that
difference *is* the delta Pricing the tool exists to explain. Asserting additivity on it
would encode a false invariant.

## 5. The snapshot (the most important artifact)

`tools/snapshot_figures.js` captures every rendered numeric value across 11 sections: the
launcher, the TRACE module, all seven TRACE-Pro tabs, plus two extra deterministic states
that expose figures the default state hides (`pro:lt@expanded`, `pro:rfx@walk`). Values are
captured exactly as rendered, in document order, from innerText, from form-control values
and from SVG text. **No normalisation, no rounding, no tolerance.** The comparison is a
byte-for-byte match of the emitted JSON, so a changed, moved, added or removed figure all
fail.

External requests are blocked during capture, because offline double-click is the product's
stated deployment mode and it is the only way the snapshot can be deterministic.

Stability was confirmed across two consecutive identical runs before any markup changed.

### Two corrections made to the snapshot tool, both before it was trusted

1. **Trailing-separator bug (pre-existing).** The tokenizer matched `$1,234,` as a figure
   when prose followed a number. The **baseline itself already contained 2 such tokens**,
   so this was a genuine extractor defect, not a way to make a diff pass. Regex changed to
   `\d(?:[\d,]*\d)?` so a token cannot end on a separator. Baseline re-recorded **from the
   pristine original**, stability re-verified.
2. **Environment metadata removed from the compared artifact.** The list of blocked URLs
   was in the JSON, so removing the CDN tags failed the figure comparison for a non-figure
   reason. It is still printed to stdout, and "no external requests" is asserted far more
   strictly by `playwright_gate.js` (zero requests) and `check_selfcontained.js` (zero
   references). Baseline re-recorded from the pristine original, stability re-verified.

Neither change weakens value comparison and no tab is excluded.

## 7. Bulk administrator marks: how it reaches the engine

The obvious seam, `reviseApplyNav()`, is **broken for the embedded dataset** and was
rejected. `buildBaseStruct()` reads `n.holder` from `EMB.nodes`, and those nodes carry no
`holder` property, so it builds a structure keyed on `undefined`. Measured: calling
`reviseApplyNav(currentNavMap())` with **no overrides at all** moves Revised MV from
2,060,610,338.29 to 2,062,198,835.86, a $1.59m change. Evidence in `tools/probe_calc3.js`.

Instead the panel assembles the struct from the look-through tree's **own path parentage,
its existing `ownpct` and its existing `mv100`**, and hands it to the app's own
`recomputeR()`. Nothing is recomputed or re-derived in new code. Proof that the seam is
correct: at zero overrides this reproduces the live engine **exactly** - all 26 funds
match, product Revised MV difference is 0. That equality is itself a test
(`bulkupload.test.js`, second case).

Per-SPV deltas are produced by pricing each accepted row **on its own through the same
engine**, so they are engine output rather than a formula. Because `recomputeR` is affine
in the overridden values, the per-SPV deltas sum exactly to the combined delta - which is
what the 12-row test asserts, to the cent, for both product NAV and Revised MV.

Rejection reasons: unknown SPV code, duplicate code, no value supplied, non-numeric value,
both market value and NAV supplied. Matching is **exact after trimming** - no case folding
and no fuzzy matching, so `SPORTB_TYPO` is rejected rather than coerced to `SPORTB`
(asserted in `rejected.test.js`).

## 9. Bugs found and fixed during the work

1. **Pricing rows were not focusable.** The roving tabindex only ran over *visible* rows,
   and a table on a hidden tab has no `offsetParent`, so the pricing table never became
   keyboard reachable. Fixed by assigning tabindex to all rows regardless of visibility.
2. **Fixed-width identity column overflowed into the VPM Symbol column.** A `max-width` on
   a table cell is only a hint. Replaced with natural sizing plus a measured sticky offset.
3. **`text-overflow:ellipsis` on the cell blanked long fund names.** `.nm` is an
   inline-block, and an inline-block that does not fit is dropped whole rather than
   clipped. Removed from the cell; `.nm` carries its own ellipsis and is capped instead.
4. Two snapshot-tool corrections, both described in section 5.

## 10. Dead ends, with the evidence that ruled them out

- **Vendoring d3/xlsx** to satisfy "no external requests": impossible here, cdnjs returns
  proxy 403.
- **`reviseApplyNav()` as the override seam**: destructive for the embedded dataset, moves
  Revised MV by $1.59m with zero overrides. See section 7.
- **`reviseModel(MAPS, ...)` as the override seam**: `MAPS` is `null` until a Position
  Report is uploaded, so it is unavailable in the shipped state.
- **A closing subtotal row per group**: adds rendered figures, incompatible with item 1.
  Escalated as B4 and resolved by the user.

## 11. Standing assumptions

- The figure snapshot is taken with all external requests blocked, matching the stated
  deployment mode (double-click, offline). Allowing real network access would make the
  baseline depend on CDN availability, which the brief lists as an immediate halt
  condition.
- `MOD_TRACE` still contains an **opt-in** service integration (`TRACE.setService(url)` /
  `?svc=`). It fires no request unless a user explicitly configures a service, which is
  why the runtime gate measures zero network requests. It was left in place because the
  TRACE module is outside this project's scope.
